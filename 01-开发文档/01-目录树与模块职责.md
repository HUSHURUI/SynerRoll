# 目录树与模块职责

> 基线日期：2026-09-15  
> 范围：项目源码、配置、测试和运行数据边界。运行任务生成的逐时刻 `.jl` 文件不逐个列出，它们属于同一生成机制的实例。

## 1. 根目录

```text
SynerRoll-jxr/
├─ app/                         Nuxt 页面、组件、样式与图标
├─ composables/api/             前端 API 与 WebSocket 客户端
├─ config/                      组件、编辑器、主题、模板和指标配置
├─ server/                      Nuxt BFF 与项目 JSON 存储
├─ state/                       useState 状态与编辑器历史
├─ types/                       TypeScript 业务与接口契约
├─ utils/                       画布、边界、导出、结果与时间工具
├─ backend/                     Julia 计算后端
├─ docs/                        设计、说明、审查与交付文档
├─ package.json                 前端依赖和脚本
├─ nuxt.config.ts               Nuxt、API Base 与 WebSocket 配置
└─ README.md                    项目入口说明，当前需要补全
```

代码定位原则：

- 页面行为先查 `app/pages/`；
- 可复用 UI 先查 `app/components/`；
- HTTP 请求先查 `composables/api/`，再查 `server/api/v1/`，最后查 Julia route/service；
- 业务类型先查 `types/` 和 `config/component-library.json`；
- 计算错误先查 `backend/services/`，再查 `backend/components/` 与 `backend/core/`；
- 数据问题先区分项目 JSON、项目 boundary.db、tasks.db、任务 timeseries.db 和容量规划数据库。

## 2. 前端页面 `app/pages/`

| 文件 | 页面职责 | 主要依赖 | 常见故障入口 |
|---|---|---|---|
| `index.vue` | 首页/导航 | Nuxt router | 入口跳转、默认页面 |
| `project.vue` | 项目列表、模板、创建、收藏、删除、导出 | `useProjectApi`、`project-templates.ts`、`ProjectCard` | 项目不显示、模板错误、删除失败 |
| `editor/[projectId].vue` | 多画布编辑器总装配 | CanvasWorkspace、PropertiesPanel、各 modal、editor/project/ui state | 画布保存、撤销、工具栏、弹窗、跨画布状态 |
| `boundary/[projectId].vue` | 边界导入、变换、关联、图表 | boundary types、project API、ECharts | 文件列解析、变换、边界关联、图表 |
| `simulation/[projectId].vue` | 项目计算配置/导出过渡页面 | project API、backend-export | 旧仿真入口与任务体系冲突 |
| `tasks/index.vue` | 任务列表与所有结果页签 | task API、task WebSocket、结果组件 | 离线开始/终止、结果、经济和灵活性；暂停/恢复仅作在线预留语义 |
| `capacity-planning/[projectId].vue` | 容量规划六步流程 | capacity API、project API、ECharts | 变量、场景、目标、优化、应用方案 |
| `result/[projectId].vue` | 旧项目结果/导出页面 | project API、backend-export | 与正式 task result 体系职责重叠 |
| `settings.vue` | 设置页 | `system-config.ts` | 设置项未真正持久化或未接运行时 |
| `profile.vue` | 用户展示页 | 页面本地逻辑 | owner/profile 仅展示，不是深度权限系统 |

超大文件风险：容量规划页、任务页、边界页和编辑器总装配承担了过多状态与业务逻辑。当前只识别“数据加载、业务计算、图表配置、弹窗状态、模板”候选边界并形成技术方案；用户评审确认前不执行文件拆分。

## 3. 前端组件 `app/components/`

### 3.1 通用控件

- `AppButton.vue`、`AppModal.vue`、`AppTabs.vue`、`AppIcon.vue`：统一按钮、模态框、页签和图标。
- `BaseInput.vue`、`BaseSelect.vue`：基础输入控件。
- `PropertyText/Number/Select/Switch/Slider/Color/MultiSelect.vue`：参数面板字段渲染器。
- `PanelSection.vue`：属性面板分区。
- `AppToastHost.vue`：全局通知展示，对应 `state/ui.ts`。

增加表单字段时优先复用 Property 系列，不要在业务页面重复实现 input/select 样式、数值解析和错误状态。

### 3.2 编辑器组件

- `CanvasWorkspace.vue`：Vue Flow 实例、节点/边变更、选择、拖放、动态总线端口、复制粘贴和视口。
- `CanvasNode.vue`：节点渲染、Handle、旋转后的端口定位。
- `LibrarySidebar.vue`：按分类/分组展示组件库并发起拖拽。
- `PropertiesPanel.vue`：节点、边、画布、组件参数和边界关联编辑。
- `EditorHeader/MenuBar/Toolbar/StatusBar.vue`：编辑器框架和工具操作。
- `ContextMenu.vue`：右键操作。
- `LayerConfigModal.vue`、`AlgorithmConfigModal.vue`、`SimulationParseModal.vue`：项目级配置入口。

### 3.3 结果组件

- 基础图表：`LineChart.vue`、`BarChart.vue`、`PieChart.vue`。
- 时序与能流：`TaskSeriesChart.vue`、`EnergyFlowChart.vue`。
- 设备出力：`DeviceOutputAnalysis.vue` 与 `device-output/` 子目录。
- 灵活性：`DeviceFlexibilityChart.vue`、`FlexibilitySeriesChart.vue`、`FlexibilityTimeSeriesEditor.vue`。

结果公式不得写在图表组件中。图表只接受已经带单位和业务含义的结果 DTO，允许做显示单位换算和抽样。

## 4. 前端 API、状态和工具

### 4.1 `composables/api/`

| 文件 | 责任 |
|---|---|
| `useApiClient.ts` | 拼接 `/api/v1`、发送 GET/POST/PUT/DELETE、解包 `ApiResponse<T>` |
| `useProjectApi.ts` | 项目、画布、时层、算法和边界配置 |
| `useTaskApi.ts` | 任务 CRUD、数据、trace、灵活性和经济结果 |
| `useTaskWebSocket.ts` | 任务实时事件、断线与消息解析 |
| `useCapacityPlanningApi.ts` | 容量变量、场景、规划任务和结果 |

调用规则：页面只调用 composable，不直接拼 BFF 或 Julia URL；composable 只描述前端契约，不做核心业务计算。

### 4.2 `state/`

- `editor.ts`：按 projectId 保存 undo/redo 历史。
- `project.ts`：项目缓存。
- `simulation.ts`：旧/通用仿真进度状态。
- `ui.ts`：Toast 与编辑器 UI 状态。

状态选择：可由 URL/服务端恢复的业务数据不应只放 useState；短暂弹窗、选择态和通知适合放 UI state；任务状态以后端为真值。

### 4.3 `utils/`

- `canvas.ts`：节点、边、总线端口、样式、几何、选择和批量操作，是编辑器核心纯函数集合。
- `boundary-sync.ts`：边界 relatedComponents 与节点 boundaryIds 的双向同步。
- `backend-export.ts`：前端项目转换为后端解析载荷的旧/辅助出口。
- `deviceOutputData.ts`：结果变量到设备/介质/单位的展示目录。
- `deviceOutputState.ts`：设备结果页本地显示状态。
- `timeLabel.ts`：前端时间标签换算。
- `project-factory.ts`：项目/模板初始化。
- `id.ts`、`clone.ts`、`download.ts`：ID、深拷贝与下载工具。

## 5. 配置与 TypeScript 契约

### 5.1 `config/`

- `component-library.json`：组件业务 schema 的主要来源。
- `component-meta.ts`：将 JSON 转为前端 ComponentDefinition，并提供分类和变量中文名。
- `component-ui-config.ts`：特定组件的 UI 图标、色彩和尺寸覆盖。
- `system-config.ts`：菜单、工具栏、项目筛选、五状态选项、公共参数和设置页。
- `theme-config.ts`：编辑器布局尺寸和颜色；目前与 CSS token 存在两套主色，需统一。
- `flexibility.ts`：灵活性运行模式/需求来源选项和标签。
- `project-templates.ts`：内置项目模板定义。

### 5.2 `types/`

- `project.ts`：Project/ProjectSummary。
- `canvas.ts`：CanvasWorkspace、CanvasData、FlowNode/FlowEdge、PageConfig、历史和选择。
- `component.ts`：组件字段、端口、介质、五状态、ComponentMeta/Definition。
- `boundary.ts`：边界 meaning、导入/变换配置。
- `simulation.ts`：时间层、算法、求解器和旧仿真结果。
- `api.ts`：项目、任务、结果和经济 API DTO。
- `capacity-planning.ts`：容量规划完整前端契约。

类型文件是编译期契约，不是运行时校验。所有外部 JSON、请求体和数据库 JSON 仍需运行时验证。

## 6. Nuxt BFF `server/`

### 6.1 项目存储

- `server/utils/project-store.ts`：读写 `server/data/projects.json`，创建/删除项目 boundary DB 目录。
- `server/utils/response.ts`：统一成功响应 `{ success, data, message? }`。

项目由 BFF 管理，计算数据由 Julia 管理。修改项目存储必须同时考虑 JSON 原子写、多画布 schema、边界 DB 路径和项目删除级联。

### 6.2 API 目录

`server/api/v1/` 按文件名映射 HTTP：

- `project/`：项目和项目级配置；
- `boundary/`：转发 Julia 边界处理；
- `task/`：转发任务和结果；
- `capacity-planning/`：转发容量规划；
- `ingest/`：转发在线时序写入。

BFF 文件应使用共享 Julia client，不应各自硬编码 `http://localhost:8080`。

## 7. Julia 后端目录

### 7.1 入口

- `backend/server.jl`：加载依赖和模块、注册边界 route、include task/capacity/ingest routes、启动恢复、CORS、health 和 HTTP 服务。
- `BackendStandardized.jl`、`BackendStandardized-Base.jl`：历史/开发执行入口，含固定任务路径，不能作为生产启动入口。

### 7.2 `backend/core/`

- `types.jl`：AbstractComponent、ComponentConfig、FieldSpec、LayerSpec、ComponentSchema、BuildContext、ResultBinding。
- `schema.jl`：读取组件 JSON schema 并构建 Julia schema cache。
- `validation.jl`：通用字段、根区段、分层区段校验和默认值填充。
- `component_framework.jl`：组件统一接口及模型调用框架。
- `flexibility.jl`：设备灵活性方向、上下文和结果类型。
- `system_flexibility.jl`：系统供给、需求、裕度和摘要类型。

### 7.3 `backend/services/`

- `parse_service.jl`：画布节点/边验证，生成 component/connection/mapping。
- `model_service.jl`：实例化组件、总线平衡、松弛、跨层爬坡、模型构建、求解和结果持久化。
- `simulation_runner.jl`：任务 parse/build/boundary/solve/flexibility 生命周期。
- `task_manager.jl`：tasks.db、TaskContext、Channel、订阅和状态。
- `boundary_service.jl`：项目边界 DB 配置、数据准备、删除和 seed 到任务。
- `economy_evaluation_service.jl`：读取任务结果并构建分层经济摘要。
- `flexibility_*_service.jl`：基准适配、设备供给、系统聚合、需求、裕度、持久化和总评估。
- `capacity_planning/`：变量识别、场景降维、候选快照、仿真评价、经济 evaluator、优化、任务上下文和存储。

### 7.4 `backend/routes/`

- `task.jl`：任务创建、列表、状态、取消、删除、connection、data、trace、灵活性、经济和 WebSocket。
- `capacity_planning.jl`：规划表单、校验、典型场景、CRUD、启动、取消和结果。
- `ingest.jl`：项目边界和在线任务时序写入。

边界的 import/transform/submit/load/delete 当前仍直接位于 `server.jl`，后续宜迁到独立 `routes/boundary.jl`。

### 7.5 `backend/utils/`

- `timeseries_utils.jl`：TimeSeries、SQLite store、data key、query、trace。
- `timestr_utils.jl`：`15m`、`1h` 和累计 `H:MM` 标签换算。
- `model_utils.jl`：时间域、JuMP model、跨层/存储历史值。
- `model_builder_utils.jl`：tracked variable/constraint/expression/objective 与代码追踪。
- `layer_utils.jl`：层 ID 和上层定位。
- `flexibility_utils.jl`：通用设备灵活性公式。
- `economy_calculator.jl`：运行成本计算。
- `server_utils.jl`：后端数据根目录和响应工具。
- `prediction_utils.jl`：预测接口占位，未来在线业务扩展点。

## 8. 组件目录模式

当前 16 类非总线组件均位于 `backend/components/<component>/`。标准六文件职责：

| 文件 | 必须内容 |
|---|---|
| `component.jl` | Julia 类型、组件 key、schema/字段、结果绑定 |
| `model-common.jl` | 所有构建方式共享的变量和约束逻辑 |
| `model.jl` | 运行时 tracked/生成模型入口 |
| `model-base.jl` | 易读的数学基准与回归参照 |
| `flexibility.jl` | 设备后验灵活性接口 |
| `validation.jl` | 组件特有物理和状态规则 |

组件目录：`wind_turbine`、`photovoltaic`、`coal_power`、`gas_power`、`combined_heat_power`、`electricity_storage`、`hydrogen_storage`、`flywheel_storage`、`pumped_storage`、`compressed_air_storage`、`electrolyzer`、`electricity_load`、`hydrogen_load`、`heat_load`、`power_grid`、`hydro_power`。

## 9. 测试目录

`backend/test/` 以组件 key 分目录，包含 case JSON、预期/生成 Julia 和少量专用 runner。现有主要目录包括 WT、PV、CP、GP、CHP、ES、HS、FS、PS、CS、ET、E_LOAD、H_LOAD、Q_LOAD、H2_BUS、THERMAL_BUS。

注意：`.gitignore` 当前忽略整个 `backend/test/`，会使测试无法正常版本管理。应只忽略 `mock_data/*.db`、generated_code 和临时输出，保留测试输入、断言和 runner。

## 10. 运行数据边界

`backend/data/` 不是源码：

- `tasks.db`：任务索引；
- `tasks/<taskId>/`：project/component/connection/mapping、generated、timeseries.db；
- `projects/<projectId>/boundary.db`：项目边界；
- `capacity-planning.db`：规划索引和评价；
- `capacity-planning/<planningId>/`：快照、配置、场景和结果。

排查代码时不要把 generated `.jl` 当作手写源码修改。需要修正其内容时，应定位生成它的组件 model、model-common、tracked builder 或 model service。

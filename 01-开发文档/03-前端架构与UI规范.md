# 前端架构与 UI 规范

## 1. 技术基线

- Nuxt 4、Vue 3 Composition API、TypeScript；
- Tailwind CSS 4 与 `app/assets/css/main.css` token；
- Vue Flow 负责画布；
- ECharts 负责结果图表；
- XLSX 负责表格导出；
- Nuxt `useState` 保存轻量跨组件状态；
- 所有业务 HTTP 经 `/api/v1` BFF。

## 2. 文件职责规范

### Page

页面负责路由参数、页面级加载、业务流程编排和主要区块布局。不应长期承载：

- 可复用的图表 option 构造；
- 大量数据转换；
- API URL；
- 组件 schema 复制；
- 经济/灵活性公式；
- 跨页面全局状态。

当 page 超过约 500 行，应先按“步骤组件 + composable + 纯函数”识别候选边界并提交技术方案。当前 capacity、tasks、boundary 页面只进入方案评审，用户确认前不执行文件拆分。

### Component

组件通过 typed props/emits 与父组件交互。通用控件不读取路由或业务 API；业务组件可调用 composable，但结果图表最好只接收 DTO。

### Composable

- 名称使用 `useXxx`；
- 封装业务 API、订阅或可复用状态逻辑；
- 返回 typed 方法和状态；
- 不直接操作无关 DOM；
- 不吞掉错误，交由页面 toast/错误区展示。

### State

- `useState` key 必须包含业务作用域，如 projectId/taskId；
- 服务端可恢复数据以后端为真值；
- 不把大时序数组长期放全局 state；
- undo/redo 快照应限制数量和内存。

## 3. TypeScript 风格

- 业务接口使用 `interface`；联合枚举和值集合使用 `type`；
- 类型从 `~~/types/*` 导入，使用 `import type`；
- 文件、变量、函数使用 camelCase；Vue 组件使用 PascalCase；常量用 UPPER_SNAKE_CASE 或语义清晰的 camelCase 配置对象；
- 不使用隐式 `any`；外部数据先视为 unknown，再进行运行时校验；
- API 字段如果必须 snake_case，应集中在 DTO/adapter，页面内部使用一致命名；
- ID 不转换为可变数组下标；
- 金额、功率和时间值必须连同单位/尺度保存。

## 4. API 规范

- 页面调用 `useProjectApi/useTaskApi/useCapacityPlanningApi`；
- composable 调用 `useApiClient`；
- 不在业务页面或 BFF 文件重复硬编码 backend URL；
- 所有成功响应为 `{ success: true, data, message? }`；
- 错误至少包含稳定 `code`、用户消息、可重试标识和开发详情 ID；
- 列表接口使用名词复数或项目现有统一风格，不再混用 `/task/list` 和 REST collection 而无文档；
- 大时序必须分页/时间窗查询；
- WebSocket 事件必须有 `type`、taskId、sequence、timestamp 和 payload schemaVersion。

## 5. UI 视觉语言

当前总体风格为企业级、浅色、信息密度较高的工程工作台：

- 页面背景：浅灰；
- 面板：白色；
- 主色：蓝色；
- 成功：绿色；警告：橙色；危险：红色；
- 圆角：编辑器局部约 6px，面板约 12px；
- 阴影：弱阴影，不使用强烈拟物；
- 中文字体：Microsoft YaHei、PingFang SC、Noto Sans CJK SC 等回退链；
- 表单高度约 32/36px；
- 文本以 12/14px 为主，标题使用中等字重。

### 当前 token 冲突

`main.css` 使用 `#0A4DA2` 为 primary，`theme-config.ts` 使用 `#165DFF`。必须确定唯一主题源，再由它生成 Tailwind/CSS、Vue Flow、ECharts 和组件配置，禁止继续双维护。

## 6. 布局规范

编辑器布局常量集中于 `config/theme-config.ts`：header 54、menu 32、toolbar 54、status 32、sidebar 300/54、property 320。新增布局不能在组件内重复写同类魔法数。

- 顶部：产品/项目上下文与主导航；
- 菜单/工具栏：画布、样式、建模动作；
- 左侧：组件库，可折叠；
- 中央：无限视图中的有限页面画布；
- 右侧：属性面板；
- 底部：状态、缩放和反馈。

## 7. 画布 UI 规范

- 节点必须始终从 ComponentDefinition 创建；
- 端口 medium 决定是否可连接和默认线色；
- 总线端口动态增加时保持稳定 ID；
- 旋转只改变显示侧，不能改变业务输入/输出方向；
- 多选操作必须形成一次 undo 历史，而不是每节点一次；
- 删除节点同步删除边，并更新边界关联；
- 保存一个画布不改变其他画布；
- 100+ 节点场景应避免深层 watch 和整 workspace 频繁深拷贝。

介质颜色以 `MEDIUM_EDGE_STYLES` 为准：electric 蓝、thermal 橙、gas 红、hydrogen 绿、material 紫、general 灰、ammonia 靛、methanol 粉、carbon 棕灰。修改时同步图例和可访问性说明。

## 8. 表单规范

- 优先使用 Property 系列控件；
- label、unit、description、min/max/step 来自 schema；
- 数值输入必须区分空值和 0；
- 失焦与提交都要校验；
- 业务警告不阻止保存，计算阻断错误必须清楚标记；
- disabled 字段要解释原因；
- 未实现目标显示“开发中”，不能只是可点击后返回近似值；
- 长表单按技术、经济、约束、目标和分层参数分区。

## 9. 图表规范

- ECharts option 构造从页面拆到专用函数/组件；
- 图表输入包含值、原始单位、显示单位、series label 和时间；
- 单位换算只在显示层，导出原始值和单位；
- 缺失值不自动当 0；
- 长时序按像素宽度降采样，缩放后请求细粒度数据；
- 正负值、收入/成本、缺额/过剩使用稳定色义；
- Tooltip 显示时间、业务名、原字段和单位；
- UUID 和模型变量默认隐藏在专家模式；
- 所有汇总卡片和图表来自相同后端结果，不能分别计算。

## 10. 状态和反馈

- 操作成功使用短 Toast；
- 可恢复错误在当前表单就地显示；
- 后台任务错误显示阶段、错误分类、原因和诊断 ID；
- 业务松弛使用警告而非程序失败红色；
- 删除项目/任务等不可逆操作需要明确对象名和数据范围；
- 加载状态应区分首次加载、后台刷新和提交；
- WebSocket 断线显示“状态更新中断”，但不暗示任务停止。

## 12. 前端测试约定

- 纯函数：Vitest，覆盖 canvas、timeLabel、unit conversion、boundary sync；
- 组件：输入、emits、disabled/error 状态；
- composable：mock BFF，验证请求和错误映射；
- 页面：关键六步流程和任务状态；
- E2E：多画布保存、边界复用、创建/取消离线任务、在线策略暂停切换恢复、容量方案应用；
- 视觉回归：项目页、编辑器、边界页、任务结果和容量六步。

## 13. 禁止项

- 页面直接读取/写入 SQLite；
- 页面硬编码 Julia URL；
- 图表重新实现经济/灵活性公式；
- 复制组件 schema 形成第三份配置；
- 使用数组位置代替稳定 ID；
- 不带单位的公共数值字段；
- catch 后静默忽略错误；
- 用 `as any` 绕过关键业务契约；
- 将测试/开发入口显示为正式客户功能。

# 全局常量、命名与单位规范

## 1. 规范的单一来源

| 内容 | 单一来源 | 生成/消费 |
|---|---|---|
| 组件 key、端口、参数、单位、支持状态 | Component Schema | TS 表单/类型、Julia 静态元数据 |
| 任务状态和事件 | Task Protocol Schema | 前端、BFF、supervisor、worker |
| 介质和边界物理含义 | Domain Schema | 组件库、边界 UI、Julia 解析 |
| UI 色彩/尺寸/语义色 | Design Tokens | Tailwind/CSS、图表、组件 |
| API 路径和 DTO | OpenAPI/共享 schema | client、BFF、Julia route |
| 数值容差和尺度策略 | NumericPolicy | 全部模型、测试、诊断 |

页面、route、组件模型不得再复制公共枚举；若需业务特有标签，应以共享 key 为索引进行扩展。

## 2. 文件和目录命名

- Vue 组件：`PascalCase.vue`；页面遵循 Nuxt 路由规则。
- composable：`useXxx.ts`；只封装一类业务能力。
- TypeScript 配置：`kebab-case.ts`；类型按领域拆分。
- Julia 文件/目录：`snake_case.jl`；组件目录使用完整英文名，如 `hydrogen_storage/`。
- 测试：与被测领域同目录或明确镜像目录；fixture 名包含场景和预期。
- 持久化目录：稳定 ASCII 标识，不使用项目名称拼路径。

## 3. 标识命名

| 语言/位置 | 规范 | 示例 |
|---|---|---|
| TypeScript 类型/接口 | PascalCase | `CreateTaskRequest` |
| TypeScript 函数/变量 | camelCase | `buildTaskSnapshot` |
| TypeScript 常量 | UPPER_SNAKE_CASE 或只读配置 camelCase；同模块统一 | `TASK_STATUS_LABELS` |
| Julia 类型/模块 | PascalCase | `TaskContext` |
| Julia 函数/变量 | snake_case | `build_model!` |
| Julia 修改函数 | 末尾 `!` | `save_task!` |
| JSON 字段 | camelCase（外部 API） | `projectId` |
| SQLite 列 | snake_case（内部库） | `project_id` |
| 事件名 | `domain.action` | `task.progress` |
| 错误码 | `DOMAIN.REASON` | `MODEL.INFEASIBLE` |

API 层负责 camelCase↔snake_case 转换；页面不得直接依赖 SQLite 列名。

## 4. ID 规则

- ID 一经创建永不因重命名改变。
- 前缀仅用于可读性：`project-`、`canvas-`、`node-`、`edge-`、`boundary-`、`task-`、`cp-`。
- 关系字段必须带语义后缀：`projectId`、`canvasId`，禁止裸 `id2` 或 `parent`。
- 组件实例 ID 和组件类型 key 分开：`nodeId=node-...`，`componentKey=WT`。
- 数据库唯一键、目录名、WebSocket topic 全部使用 taskId，不使用任务显示名。

## 5. 介质、端口和变量

已使用介质包括 `electric`、`heat/thermal`、`gas`、`hydrogen`、`material`、`general`。当前 `parse_service.jl` 有介质前缀映射，建议统一为：

| 规范 medium key | 变量前缀 | 说明 |
|---|---|---|
| `electric` | `E` | 电功率/电能流 |
| `heat` | `Q` | 热功率/热能流；不得同时混用 thermal 作为同层 key |
| `gas` | `G` | 气体能流 |
| `hydrogen` | `H` | 氢能流 |
| `material` | `M` | 物料流 |
| `general` | `X` | 无明确介质的扩展接口 |

端口 ID 格式建议 `<medium>-<direction>-<ordinal>`；direction 为 `in|out|bidirectional`。连线必须校验介质兼容、方向、重复连接规则和节点存在。

模型变量建议 `<mediumPrefix>_<semantic>_<componentCode>`；状态/二进制变量用稳定语义前缀，不依赖希腊字母作为唯一机器标识。显示名另由元数据映射。

## 6. 单位规范

- 内部功率统一 kW，能量 kWh，时间小时，货币元；若业务决定改为 MW/MWh，应整体迁移，不允许混用。
- UI 输入必须显示单位；DTO 关键数值采用 `value + unit` 或字段名明确单位，如 `powerKw`。
- 百分比内部存 0–1 还是 0–100 必须按字段固定；推荐比例存 0–1，UI 转换。
- 效率范围 0–1；角度、温度、压力等在 schema 中声明单位和允许范围。
- 时间层 length/step/forward 当前使用 `168h/60m` 字符串，解析只能经统一 Duration parser。
- 经济量区分 CAPEX、固定 O&M、可变 O&M、燃料、购售能、启动、替换、收入和惩罚；不得都叫 cost。

## 7. 全局常量登记

当前需集中迁移的常量：

| 当前项 | 位置 | 当前值/问题 | 目标 |
|---|---|---|---|
| HTTP 端口 | `backend/server.jl` | 8080 默认 | `AppConfig.httpPort` |
| WS 地址 | `nuxt.config.ts` | `ws://localhost:8080` | runtime endpoint |
| 数据根目录 | 多处 | `@__DIR__`/cwd | 绝对 `dataRoot` |
| `BIG_M` | `backend/utils/model_utils.jl` | `1e10` | `derive_big_m` |
| `SLACK_BIG_M` | `model_service.jl` | `1e8` | NumericPolicy |
| `SLACK_PENALTY_DEFAULT` | `model_service.jl` | `1e6` | 按目标尺度推导 |
| failure penalty | capacity planning | `1e18` | 结构化不可行结果或受控上界 |
| 多处容差 | core/services/components | `1e-6/1e-9` 等 | 容差分级常量 |
| 最大层回退 | `model_service.jl` | 3 | 禁止回退，参数必填 |
| 主题主色 | CSS/theme config | 两套蓝色 | 唯一 design token |
| 状态标签/色调 | tasks/capacity 页面 | 页面重复 | 状态语义配置 |

常量登记项必须注明：语义、单位、作用域、默认值、可配置性、验证范围和修改影响。

## 8. UI 设计令牌

当前正式 CSS 以 `assets/css/main.css` 的 `#0a4da2` 为主色；`config/theme-config.ts` 的 `#165DFF` 尚未检出有效消费且与之冲突。后续只保留一套 token：

- 颜色：primary、surface、panel、border、text、muted、success、warning、danger；
- 尺寸：header/menu/toolbar/status/sidebar/property；
- 圆角：input/card/dialog；
- 阴影：card/floating/dialog；
- 图表：分类色板、正负/上下调、告警色；
- 状态：pending/running/completed/failed/cancelled 等语义色。

组件使用 token，不写十六进制；ECharts 配置通过共享 chart theme 取色。

## 9. 状态与能力命名

- 组件运行状态：`stand_alone|disabled|fixed_state|adjust_power|full_follow`。
- 离线任务状态不含 paused；在线任务可扩展 paused/switching/resuming。
- `online/offline` 是任务模式，不是运行状态。
- capacity planning 有独立状态，但公共终态 key 尽量一致。
- API 返回 capability，例如 `controls:["cancel"]`，UI 据此展示按钮，禁止按状态猜测后端是否支持。

## 10. 注释和废弃规则

- 注释解释“为什么”和约束，不复述代码。
- 临时注释代码不得长期保留；迁移完成后删除，历史由版本控制保存。
- 废弃 API 标记 deprecated、替代路径和删除版本；只返回 410 的 route 在客户端迁移完成后删除。
- TODO 格式：`TODO(RISK-ID|PLAN-ID): 内容`，例如 `TODO(R10/K-201): worker process isolation`。
- 口语需求转为代码前先落入本开发文档或 ADR，不直接复制口语为注释。
